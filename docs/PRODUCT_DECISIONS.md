# Audit and product decisions

| Severity | Finding                                                                                                | Decision / fix                                                                                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CRITICAL | Greedy separate residual visits can overcharge minimums and miss the best shift set.                   | Exact dynamic programming across all 15-minute visit placements; allow bridging free gaps, charge entire visit, prohibit overlapping or touching separate visits. Exhaustive independent oracle validates small schedules. |
| CRITICAL | A minimum charge without an actual available visit creates phantom care.                               | Every returned visit fits unioned continuous availability and satisfies actual minimum duration. Return exact unsatisfied care on failure.                                                                                 |
| HIGH     | No time zone exists in v1, so browser-local DST validation is unreliable for US users abroad.          | Add explicit supported US IANA timeZone; use wall-time arithmetic independent of machine zone and reject DST weeks.                                                                                                        |
| HIGH     | Unbounded money, interval lists and ambiguous fractional withholding undermine validation/performance. | Rate/cost limit $10,000, 28 windows/category, 15-minute durations, 0–60% withholding to 0.01%. Explicit errors rather than truncation.                                                                                     |
| HIGH     | Stale result can look like a recommendation for changed inputs.                                        | Recompute after edits once optimization started; invalid inputs hide results.                                                                                                                                              |
| MEDIUM   | A care cost alone does not explain who covers time.                                                    | Show explicit coverage by source and full paid visits, distinguish entered availability from booking.                                                                                                                      |
| MEDIUM   | Single-parent data could retain hidden partner coverage.                                               | Clear partner slots on mode change and reject inconsistent engine input.                                                                                                                                                   |
| LOW      | Large landing page delays value.                                                                       | Compact introduction and single planning workspace, sample runs through real engine.                                                                                                                                       |

Unchanged: target user, marginal-income objective, one sitter, no backend, exhaustive shift subsets, integer cents, 15-minute precision, explicit free care, empty baseline, scope limits and required demo numbers.

P0 includes no real-world tax or legal eligibility inference. Provider rate is assumed to cover the household; no assumptions about number or needs of children. Unsupported cases are visible in the product.

Delivery: existing public repository owner is taken from origin, not invented. Static GitHub Pages is an acceptable fallback to preferred Vercel if available access supports it. Pitch evidence is in scope; deck authoring/submission stays with captain per directive.
